# LangGraph & VS Code Troubleshooting & Setup Guide

---

### **Q1: Why is VS Code unable to navigate to `typing.TypedDict` using F12 (Go to Definition)?**
**A:** `TypedDict` is imported from Python’s standard library `typing` module. F12 navigation fails if VS Code lacks an active Python language server or an assigned interpreter. To fix this:
1. Ensure the **Pylance** extension is installed and enabled.
2. Run **Python: Select Interpreter** (`Cmd+Shift+P` or `Ctrl+Shift+P`) and select the correct Python environment.
3. Ensure the file’s language mode is set to **Python** (not Plain Text).

---

### **Q2: Is the assistant or Copilot generating code chunks when pressing Tab?**
**A:** The automatic gray text code suggestions accepted by pressing **Tab** are provided by **GitHub Copilot inline suggestions**, not Python IntelliSense/Pylance. VS Code handles these via two separate systems:
* **Pylance:** Handles core Python intelligence, type hints, error checking, and F12 definition lookup.
* **GitHub Copilot:** Generates multi-line code predictions on the fly.

---

### **Q3: How do you turn the GitHub Copilot assistant on and off in VS Code?**
**A:** You can control Copilot through the following methods:
* Click the **Copilot icon** in the status bar/title bar and choose **Disable** or **Enable**.
* Open the Command Palette (`Cmd+Shift+P` / `Ctrl+Shift+P`) and execute `GitHub Copilot: Disable` or `GitHub Copilot: Enable`.
* To turn off only the gray code predictions without disabling the whole assistant, go to **Copilot Icon → Inline Suggestions → Enable/Disable**.

---

### **Q4: Why is "Go to Definition" (F12) failing specifically for `StateGraph`?**
**A:** When `StateGraph` is importable in the code but "Go to Definition" fails, the primary reasons are:
1. **Shortcut conflict (macOS):** F12 might be captured by macOS system keys. Use **Cmd+Click**, **Fn+F12**, or right-click `StateGraph` → **Go to Definition**.
2. **Interpreter Mismatch:** VS Code's active interpreter differs from the execution environment (e.g., `uv run` pointing to a parent directory `.venv` while VS Code is pointing elsewhere).

---

### **Q5: How can a project-local virtual environment (`.venv`) be populated and linked to VS Code?**
**A:** Run the following steps in the project root:
1. Force `uv` to populate the project's local environment:
   ```bash
   UV_PROJECT_ENVIRONMENT="$PWD/.venv" uv sync
   ```
2. In VS Code, open the Command Palette (`Cmd+Shift+P` / `Ctrl+Shift+P`).
3. Select **Python: Select Interpreter** and choose `hello-langgraph/.venv/bin/python`.
4. Reload the VS Code window.

### **Q6: Why did `uv run python src/hello_agent_1.py` fail with `[Errno 2] No such file or directory`?**
**A:** The relative file path supplied was incorrect. The source file was nested inside a module subdirectory: `src/hello_langgraph/hello_agent_1.py`. 

To run it correctly, use:
```bash
UV_PROJECT_ENVIRONMENT="$PWD/.venv" uv run python src/hello_langgraph/hello_agent_1.py
```

---

### **Q7: Why did `uv run python src/hello_langgraph /hello_agent_1.py` throw `can't find '__main__' module`?**
**A:** There was an accidental extra space between the path directory and filename (`src/hello_langgraph /hello_agent_1.py`). Python interpreted `src/hello_langgraph` as a module folder rather than a script path, resulting in a search for an internal `__main__.py` file.

---

### **Q8: Why did `state_graph.add_edge(add, subtract)` throw an error at line 62 in the script?**
**A:** LangGraph expects **string names** for node transitions, not direct Python function references. Because nodes were registered with strings (`state_graph.add_node("add", add)`), edges must be connected using string names:

```python
state_graph.add_edge(START, "add")
state_graph.add_edge("add", "subtract")
state_graph.add_edge("subtract", "multiply")
state_graph.add_edge("multiply", END)
```

### **Q9: How do you configure and launch LangGraph Studio UI locally using `langgraph dev`?**
**A:** 
1. Create a `langgraph.json` file in your **project root**:
   ```json
   {
     "dependencies": ["."],
     "graphs": {
       "agent_1": "./src/hello_langgraph/hello_agent_1.py:graph"
     }
   }
   ```
2. Launch the local development server:
   ```bash
   UV_PROJECT_ENVIRONMENT="$PWD/.venv" uv run langgraph dev --port 8123
   ```
3. Open the studio link provided in the terminal (e.g., `https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:8123`).

---

### **Q10: Why did LangGraph Studio fail with the error `FileNotFoundError: [Errno 2] No such file or directory: '.../.src/hello_agent_1.py'`?**
**A:** The path specified inside `langgraph.json` contained a typo (`.src/hello_agent_1.py` instead of `./src/hello_langgraph/hello_agent_1.py`). Updating `langgraph.json` with the correct relative path resolves the issue.

---

### **Q11: How do you fix the error `Failed to connect to Agent Server because the domain "unknown" is not allowed`?**
**A:** This happens when LangGraph Studio does not receive the base URL of your active local server. To resolve it, click **Configure** in the UI and enter the exact running address with its port (e.g., `http://127.0.0.1:8123`). Make sure the local server process stays active in your terminal while using the web interface.

---

### **Q12: What causes the browser error `URL.canParse is not a function` when opening LangGraph Studio?**
**A:** `URL.canParse()` is a newer JavaScript API supported only in recent browser releases. This is an outdated browser/environment compatibility issue. To fix it, open the Studio link in the latest version of Chrome or Edge, update Safari/macOS, or avoid opening the link inside VS Code's embedded webview.
